## 규칙 6가지

### 1. 트랙별 전용 파일 — 남이 안 건드림

| 트랙 | 전용 파일 |
|---|---|
| 홍보마케팅비서 | `promo_skill.js` · `docs/promo/*` |
| 보상비서 | `claim_*.js` · `fonts/*` · `_test_claim_*.js` |
| 캠페인·발송 | `campaign_skill.js` · `campaign.html` |
| 기억·벡터창고 | `personal_memory.js` · `memory_module.js` · `_diag_pinecone.js` |
| 결재함 | `approval_skill.js` |

전용 파일은 표에 적을 필요 없습니다. 겹칠 일이 없습니다.

### 2. 공용 파일 2개는 "짧게 잡고 바로 놓기"

`deploy/genya.html` · `deploy/main_server.js`

1. 손대기 직전 **`git pull`** — 남의 최신 변경을 먼저 받는다
2. **한 곳만, 최소 줄수로** 고친다
3. 고치면 **곧바로 커밋** — 몇 시간씩 미커밋으로 들고 있지 않는다
4. 커밋 전 **`git status`** 확인 — 남이 미커밋으로 들고 있으면 **기다린다**

### 3. 새 기능은 무조건 독립 모듈

CLAUDE.md 6-2 ⑦(기존 기능 22블록 보존)과 같은 원칙입니다.

공용 파일에는 **`require` + 라우터 마운트 1~3줄만** 넣고,
나머지 코드는 전부 **새 파일**에 넣습니다.

### 4. 배포 리포트에 "남의 커밋"을 반드시 적는다

`git push` 하면 **먼저 올라와 있던 남의 커밋도 함께 배포**됩니다.
배포 보고할 때 **내 커밋 외에 무엇이 함께 나갔는지** 적습니다.

확인 방법:
```
git log --format='%h | %ad | %s' --date=format:'%m-%d %H:%M' <이전헤드>..<내커밋>
```

### 5. 이 표는 사람이 지켜야 작동한다

코드가 막아주는 게 아닙니다. **각 세션이 적고 지워야** 의미가 있습니다.
팀장이 세션들에 공지해 주셔야 합니다.

### 6. ★브랜치를 전환하기 전에 표시판에 적는다

**브랜치 전환은 파일 하나 잡는 것보다 훨씬 위험합니다.**
파일 하나는 그 파일만 바뀌지만, **브랜치 전환은 워킹트리 전체를 바꿉니다.**
다른 세션이 편집 중이던 파일이 통째로 다른 내용으로 갈아치워질 수 있습니다.

**규칙**

1. 브랜치를 바꾸기 전에 아래 표에 적는다 — 파일 칸에 `(브랜치 전환)` 이라고 씁니다
2. **다른 세션이 커밋 준비 중이면 기다린다**
3. 전환한 뒤에도 표를 지우지 않는다 — **되돌릴 때까지** 남겨 둡니다

**내 커밋이 엉뚱한 브랜치에 올라갔을 때 (안전한 처리법)**

브랜치를 되돌리려 하지 마십시오. 다른 세션 작업이 파괴됩니다.
대신 **체크아웃 없이 커밋만 원격 main으로 보냅니다.**

```
git log --format='%h %p' -1 <내커밋>     # 부모가 main 헤드인지 확인
git push origin <내커밋>:main            # 로컬 브랜치 전환 안 함
```

부모가 main 헤드가 아니면(갈라졌으면) **혼자 판단하지 말고 팀장에게 보고**합니다.

## 실제로 있었던 일 (2026-07-29)

### ① 같은 파일 동시 수정 — 아슬아슬하게 안 겹침

| 시각 | 트랙 | 일 |
|---|---|---|
| 16:17 | 보상비서 | `genya.html` 8줄 고쳐 커밋 |
| 16:56 | 홍보마케팅비서 | 같은 파일 7줄 고쳐 커밋 |

**서로 다른 줄이라 안 겹쳤습니다. 겹쳤으면 한쪽이 덮였습니다.**
같은 날 홍보마케팅비서 배포에 보상비서 커밋 2건이 함께 실려 나갔습니다.

### ② 브랜치가 바뀌어 커밋이 엉뚱한 곳에 들어감

| 시각 | 일 |
|---|---|
| 17:5x | 약관 세션이 `feature/yakgwan-shared` 브랜치를 만들어 체크아웃 |
| 17:5x | 홍보마케팅비서가 main용 커밋(`e00879a`)을 만듦 → **그 브랜치에 얹힘** |

그대로 뒀으면 **Render는 main만 배포하므로 아무것도 안 나갔을 것**입니다.

**처리:** 브랜치를 전환하지 않고 `git push origin e00879a:main` 으로 커밋만 보냄.
부모가 정확히 main 헤드였고 바뀐 파일도 하나뿐이라 안전했습니다.
**다행히 fast-forward가 가능했던 것이지, 일반적으로는 매우 위험합니다.**
