### ★핵심 변화 (개선안 4)

**"1,500자 내외" 같은 글자 수 지시를 버리고, 구조(섹션 수) + 항목별 상한으로 바꿉니다.**

근거 — 1차 실측에서 **구조를 센 것**(카드뉴스 10장·스레드)은 100~127%로 정확했고,
**글자 수만 준 것**(팟캐스트)은 66%였습니다.

**목표를 낮춘 게 아니라, 산술적으로 불가능했던 숫자를 가능한 값으로 고친 것입니다.**

## 3. max_tokens 공식 (개선안 부수)

```js
max_tokens = max(기존값, ceil(목표자수 × 1.6) + 1200)
```

- `1.6` = 한글 1자당 토큰 실측치 (1차 실측 4,013토큰/3,321자 ≈ 1.21 + 여유)
- `+1200` = 안전 마진. 1차에서 이미지·쇼츠가 **91%까지 차서 위험**했음

### ★반드시 함께: `thinking: { type: 'disabled' }`

Sonnet 5는 **생각이 기본 ON** 이고 `max_tokens` 를 **생각과 본문이 나눠 씁니다.**
안 끄면 생각이 예산을 다 먹어 **본문 0자**가 됩니다.

**프로덕션 실사고로 확인됨** — `/api/promo/draft` 가 7회 중 3회 빈 화면, 2회 잘림.
`thinking` 을 끄면 8/8 정상(토큰 142~209/900).

## 5. 자동 검사 + 1회 보강 (개선안 5)

```
생성 → 글자수 측정
  ├ 목표의 80~120% 안  → 통과 (보정 "—")
  ├ 80% 미만           → 1회 보강: "N자 짧다. 각 항목 분량을 채워 다시 써라.
  │                              내용을 새로 지어내지 말고 기존 내용을 더 자세히 풀어라."
  └ 120% 초과          → 1회 압축: "N자 길다. 핵심 유지한 채 줄여라."

재요청은 종류당 최대 1회. 2회 이상 반복하지 않음(비용·시간 폭증 방지)
```

### ★거짓 성공 금지 가드 필수 (CLAUDE.md 6-7)

```js
if (!text.length) throw new Error(`빈 응답(stop=${stop_reason}, ${출력토큰}/${max})`);
```

1차 재실측 때 **9종이 0자인데 스크립트가 `OK` 로 표시한 사고**가 있었습니다.
"진단이 거짓말한 것"이며, 반드시 막아야 합니다.
