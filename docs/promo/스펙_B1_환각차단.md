# 스펙 B-1 · 환각 차단 (`deploy/promo_skill.js`)

> 상태: **초안 · 코드 미작성** · 팀장 검수용
> 작성: 2026-07-29 · 홍보마케팅비서 Phase 0

## 왜 필요한가 — 실제로 난 사고

2차 재실측 팟캐스트 원고(`재실측결과_v2.md` 204·216·218줄)에서:

> "디자이어. … 여기서는 **다섯 글자, 다섯 가지 항목**의 앞글자를 딴 겁니다."
> "방향, 실행력, 안정성, 정보력, 회복력. **이 다섯 가지**를 하나의 진단으로 묶은 게 디자이어입니다."

**틀린 점 2가지**

1. DESIRE는 **여섯 글자(D-E-S-I-R-E)** 인데 "다섯 글자"라고 3번 반복
2. 다섯 항목 이름이 실제 오원트 DESIRE와 같은지 알 수 없음 — 어느 쪽이든 **지어낸 것**

**중요한 관찰:** 1차 실측(팟캐스트 3,321자)에는 이 오류가 **없었습니다.**
2차에서 4,695자로 길어지자 채울 내용이 없어 지어냈습니다.
→ **분량이 늘수록 환각이 늘어난다.**

## 1. 시트 「캠페인」 탭 새 컬럼

| 컬럼명 | `내용_사실자료` |
|---|---|
| 위치 | 「캠페인」 탭 · `톤앤매너` 다음 |
| 형식 | **`키: 값` 한 줄씩** (여러 줄 텍스트) |
| 한도 | 구글 시트 셀 5만 자 — 충분 |
| 채우는 사람 | 회장님 (`docs/promo/사실자료_양식.md` 참고) |
| 비어 있어도 | **원고는 정상 생성** (일반 톤) ← 회장님 지시 |

### 입력 예시 (한 칸 안에)

```
DESIRE약자: 재무 목표 달성을 위한 6단계 진단 도구
D: Debt(부채) — 새는 돈부터 막는 단계
E: Emergency(비상자금) — 3~6개월치 확보
CTA_부트캠프: 1분 무료 진단으로 내 위치부터 확인하세요
대표경력: CFP 25년 · 오원트금융연구소 대표
금지표현: 확정수익, 원금보장
```

### 미기재로 보는 값

`빈 줄` · `없음` · `____` · `-` · `미정`

→ 회장님이 "없음"이라고 적으셔도, 아예 안 적으셔도 **똑같이 "모르는 항목"으로 처리**합니다.

### 인식하는 키 목록 (양식 10개 항목과 1:1)

| 키 | 양식 항목 | 없으면 금지되는 것 |
|---|---|---|
| `DESIRE약자` | 1번 | DESIRE가 무엇의 약자인지 |
| `D` `E` `S` `I` `R` `E2` | 2번 | 각 글자 뜻·항목 나열·개수 언급 |
| `집짓기1`~`집짓기8` | 3번 | 8단계 내용·단계 이름 |
| `오행1`~`오행5` | 4번 | 5요소 내용 |
| `진단_수입지출` `진단_자산부채` `진단_연금` | 5번 | 진단이 무엇을 보는지 |
| `CTA_재무상담` `CTA_부트캠프` `CTA_일반강의` `CTA_전문가강의` | 6번 | CTA 문구 창작 |
| `대표경력` `대표숫자` `금지표현` | 7번 | 경력·수치 언급 |
| `회사명` `부트캠프명` `가격허용` `가격` | 8번 | 가격·정식명칭 |
| `진단5분_대상` `진단5분_문항` `진단5분_결과` `진단5분_CTA` | 9번 | 5분 진단 구성·문항 수 |
| `오원트미션` `지니야정의` `지니야대상` `지니야차별점` | 10번 | 브랜드 정의 |

## 2. 코드 초안

```js
// ═══════════════════════════════════════════════════════════════
// promo_skill.js · [환각 차단] 사실자료 파서 + 프롬프트 주입
//   무엇을·왜: 지니야가 DESIRE를 "다섯 글자"라 하고 항목 5개를 지어낸 사고(실측)를 막는다.
//              회장님이 시트에 적어주신 사실만 쓰고, 안 적힌 건 구체적으로 말하지 않는다.
//   ★원고는 사실자료가 비어도 정상 생성된다(회장님 지시). 일반 톤으로만 쓸 뿐이다.
//   ★서버 저장 0 — 시트를 읽어 프롬프트에 넣고 끝. 개인정보 없음.
// ═══════════════════════════════════════════════════════════════
'use strict';

// 미기재로 보는 값 — 회장님이 "없음"이라 적으셔도 안 적으셔도 같게 처리
const _EMPTY = /^(없음|미정|해당없음|[-_\s]*)$/;

// 키 → 이 키가 없을 때 금지할 주제
const FACT_KEYS = {
  DESIRE약자: 'DESIRE가 무엇의 약자인지',
  D: 'DESIRE의 D가 무엇인지', E: 'DESIRE의 E가 무엇인지',
  S: 'DESIRE의 S가 무엇인지', I: 'DESIRE의 I가 무엇인지',
  R: 'DESIRE의 R가 무엇인지', E2: 'DESIRE의 마지막 E가 무엇인지',
  집짓기1: '금융집짓기 1단계', /* …8까지 */
  오행1: '금융오행 1요소',     /* …5까지 */
  진단_수입지출: '수입지출 진단이 무엇을 보는지',
  CTA_부트캠프: '부트캠프 CTA 문구',
  대표경력: '오상열 대표의 경력·자격',
  대표숫자: '오상열 대표 관련 숫자(구독자·회차·연차 등)',
  가격: '교육비·구독료 금액',
  진단5분_문항: '5분 진단의 문항 수·구성',
  오원트미션: '오원트금융연구소의 미션',
  지니야정의: '지니야가 무엇인지',
  // … 양식 10개 항목 전부
};

// ── 시트 한 칸(내용_사실자료)을 파싱 ──────────────────────────
function parseFacts(cell) {
  const filled = {};   // 채워진 것
  const missing = [];  // 비어 있는 것(금지 대상)
  String(cell || '').split(/\r?\n/).forEach((line) => {
    const m = line.match(/^\s*([^:：]+)[:：]\s*(.*)$/);
    if (!m) return;
    const key = m[1].trim();
    const val = m[2].trim();
    if (!FACT_KEYS[key]) return;            // 모르는 키는 무시(오타 방지)
    if (_EMPTY.test(val)) return;           // 값이 비면 채운 걸로 안 봄
    filled[key] = val;
  });
  Object.keys(FACT_KEYS).forEach((k) => { if (!filled[k]) missing.push(k); });
  return { filled, missing, hasAny: Object.keys(filled).length > 0 };
}

// ── 프롬프트에 넣을 블록 만들기 ──────────────────────────────
function factBlock(facts) {
  const out = [];

  // ① 채워진 것 — 이 문장만 쓰게 한다
  if (facts.hasAny) {
    out.push('<사실자료> ★아래는 회장님이 확인해 주신 사실이다. 이 문장을 그대로 쓴다.');
    out.push('  바꿔 말하거나 살을 붙이지 마라. 여기 없는 내용을 이 주제에 덧붙이지 마라.');
    Object.entries(facts.filled).forEach(([k, v]) => out.push(`  · ${k} = ${v}`));
    out.push('</사실자료>');
  }

  // ② 비어 있는 것 — 구체적 창작을 막는다 (원고 자체는 계속 쓴다)
  if (facts.missing.length) {
    out.push('<모르는것> ★아래 항목은 확인된 사실이 없다. 절대 지어내지 마라.');
    facts.missing.forEach((k) => out.push(`  · ${FACT_KEYS[k]}`));
    out.push('  이 항목들에 대해서는:');
    out.push('   - 구체적인 정의·풀이·항목 이름을 쓰지 않는다');
    out.push('   - 개수를 말하지 않는다 ("5가지", "8단계" 같은 표현 금지)');
    out.push('   - 숫자·수치·연차·금액을 쓰지 않는다');
    out.push('   - 약자를 글자별로 풀지 않는다');
    out.push('  ★대신 이름만 쓰고 일반적인 톤으로 넘어간다. 원고는 정상적으로 완성한다.');
    out.push('  예) O "DESIRE 진단으로 지금 내 위치를 확인할 수 있습니다."');
    out.push('      X "DESIRE는 다섯 글자로, D는 방향성, E는 실행력…"');
    out.push('</모르는것>');
  }
  return out.join('\n');
}

module.exports = { parseFacts, factBlock, FACT_KEYS };
```

## 3. 빈 항목 강제 규칙 — 프롬프트에 실제 들어가는 문구

- 구체적인 정의·풀이·항목 이름을 쓰지 않는다
- **개수를 말하지 않는다** ("5가지", "8단계" 같은 표현 금지)
- 숫자·수치·연차·금액을 쓰지 않는다
- **약자를 글자별로 풀지 않는다**
- 대신 이름만 쓰고 일반적인 톤으로 넘어간다. **원고는 정상적으로 완성한다.**

### 왜 이렇게 썼나

**"개수를 말하지 않는다"를 따로 넣은 이유**
실측 사고가 *"다섯 글자, 다섯 가지 항목"* 이라는 **개수 주장에서 시작**됐습니다.
개수를 막으면 나열도 막힙니다.

**좋은 예/나쁜 예를 함께 넣은 이유**
금지만 나열하면 모델이 그 주제를 통째로 회피하거나 어색해집니다.
**"이렇게 쓰면 된다"** 를 보여줘야 원고가 자연스럽게 완성됩니다.

## 6. 정직하게 짚는 한계 3가지

1. **완벽히 막지는 못합니다.**
   프롬프트 규칙이지 코드 차단이 아닙니다. 확률을 크게 낮출 뿐입니다.
   → **검사 정규식**으로 금지 표현이 나오면 **1회 재생성**하는 안전망 제안 (승인 필요)

2. **키 이름을 회장님이 정확히 써주셔야** 인식합니다.
   오타는 무시됩니다(잘못 주입보다 안전한 쪽).
   → 화면에 **"인식된 항목 N개 / 미기재 M개"** 표시 제안

3. **양식(마크다운)과 시트 입력(키:값)의 형태가 다릅니다.**
   회장님이 양식을 채운 뒤 옮겨 적으셔야 합니다.
   → **양식을 그대로 붙여넣어도 파싱되게** 확장 가능 (승인 필요)
