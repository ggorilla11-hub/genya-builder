# CLAUDE.md — 지니야(genya-app) 작업 규칙

이 파일은 클로드 코드가 세션마다 읽는 **규칙서**입니다.
작업 일지가 아닙니다. 오늘 뭘 했는지는 깃에 남습니다.

**코드 구조 설명은 넣지 않습니다.** 그건 직접 읽으면 됩니다.
코드만 봐서는 알 수 없는 것만 적습니다.

**이 파일에 적힌 것은 전부 확정된 규칙입니다.**
확인되지 않은 내용은 넣지 않습니다.

## 2. 브랜치 규칙

- 프론트엔드 작업은 **develop 브랜치에서만** 합니다.
- **main에 직접 커밋하지 않습니다.**
- 머지 전에 반드시 사람에게 확인받습니다.

### develop → main 최종 머지 전에는 전체 검수

법무 / 프로그램 / 시스템 / UX·UI / 비즈니스 로직 — 5개 항목을 검수합니다.
**클로드가 머지 전에 이 검수를 먼저 상기시킵니다.**

## 3. 아직 안 고친 문제

### 3-1. 음성 복귀 시 맥락 유실 (미해결)

음성 대화를 하다가 끊고 다시 연결하면 앞 대화를 기억하지 못합니다.

- 원인: Vapi Assistant 프롬프트에 이전 대화를 넘겨줄 자리가 없음
- 해결 방향: `{{resumeContext}}` 변수를 프롬프트에 심고,
재연결 시 직전 대화 요약을 넣어서 시작
- **음성을 옮길 때 처음부터 설계에 포함시킬 것**

### 3-2. 음성 기능 이전 미완료

음성 기능은 아직 **다른 레포에 있습니다.**

- **새로 개발하지 말고 기존 코드를 그대로 옮깁니다.**
- 원본 위치는 대표에게 물어보세요.

## 4. 기획 원칙 (어길 수 없음)

### 4-1. 고객 데이터는 반드시 조회한 뒤에만 말한다 ⚠️ 최우선

**AI가 고객 정보를 지어내는 사고가 실제로 발생했습니다.**
없는 명단 13명의 이름·보험상품·만기일을 만들어냈습니다.

시스템 프롬프트에 아래 규칙이 반드시 들어가야 합니다.

```
1. 고객 수, 이름, 연락처, 만기일, 계약 내용은
DB 조회 도구를 실행한 뒤에만 말한다.
2. 도구를 실행하지 않았으면
"지금 확인해 볼게요" 하고 도구를 먼저 부른다.
3. 조회 결과가 비었으면 "명단에 없습니다"라고 말한다.
추측하지 않는다. 예시를 만들지 않는다.
4. 이전 대화에서 본 숫자나 이름을 다시 말할 때도
반드시 다시 조회한다.
```

**4번이 핵심입니다.** 이게 없으면 어제 본 명단을 오늘 또 읊습니다.
보험 만기일 하나 틀리면 실제 영업 사고입니다.

### 4-2. 발송은 사람이 누른다 (human-in-the-loop)

AI가 메일·문자·카톡을 **자동 발송하지 않습니다.**
쓰기 동작은 반드시 승인 대기 상태로 반환합니다.

```javascript
{ status: "needs_approval", preview: { ... } }
```

사용자가 화면에서 확인하고 버튼을 눌러야 나갑니다.

### 4-3. 고객 데이터는 오원트로 들어오지 않는다 (zero data ingress)

- 신청자 데이터는 **설계사 본인의 구글시트/DB**에 쌓입니다.
- 오원트 서버에 고객 개인정보를 저장하지 않습니다.
- 테넌트마다 자기 계정으로 연결합니다. **계정 공유 금지.**
- 오원트 계정 하나로 여러 고객 데이터를 만지면 **법적 문제**가 됩니다.

### 4-4. 무료가 유료를 잠식하지 않는다

무료 기능은 유료로 넘어오게 만드는 미끼입니다.
무료에 기능을 더 넣자는 판단이 필요하면 **사람에게 먼저 묻습니다.**

### 4-5. AI기본법 준수 (2026-01-22 시행)

- AI가 답변한 것임을 사용자가 알 수 있게 표시합니다.
- 고지·동의 절차를 임의로 생략하지 않습니다.

## 5. 지니야의 말투 (제품 사양)

취향이 아니라 **제품 사양**입니다.

1. **기억하고 먼저 이끈다** — 지난 결정을 먼저 꺼냅니다.
   "이거 하기로 하셨죠?"
2. **선택지를 늘어놓지 않는다** — 추천 하나를 밀고 "할까요?"만 묻습니다.
   - ❌ "A, B, C 중에 뭘 하실래요?"
   - ⭕ "팀장은 A를 추천합니다. 진행할까요?"
3. **쉽게 말한다** — 전문용어 대신 쉬운 말. 문장은 짧게.
   고객은 1인사업자이고 컴퓨터 초보도 있습니다.
   **어려운 말을 쓰는 순간 제품이 실패합니다.**

## 8. 이 파일 관리

### 8-1. 수정 권한 — 대표만 ⚠️

**클로드 코드는 이 파일을 임의로 고치지 않습니다.**
규칙을 지키는 쪽이 규칙을 마음대로 바꾸면 규칙이 아닙니다.

```
제안은 AI가, 결정은 사람이.
```

절차:
1. 클로드가 **"이걸 CLAUDE.md에 넣을까요?"** 라고 먼저 묻는다
2. 대표가 **예 / 아니오**
3. 승인된 것만 반영한다

**대표 승인 없이 이 파일의 줄을 추가·수정·삭제하지 마세요.**
(오탈자 수정도 포함입니다. 물어보고 하세요.)

### 8-2. 하루 작업이 끝날 때

클로드가 먼저 물어봅니다.

> "오늘 새로 정한 **규칙**이 있습니다. CLAUDE.md에 넣을까요?"

없으면 묻지 않습니다.

### 8-3. 판단 기준

> **"3개월 뒤에도 이게 맞나?"**

- 맞으면 → 넣는다 (예: "발송은 사람이 누른다")
- 아니면 → 안 넣는다 (예: "오늘 로그인 버그 고침")

### 8-4. 넣지 않는 것

- 코드 구조·함수 설명 (금방 거짓말이 됩니다)
- 확인되지 않은 내용 (**추정을 규칙처럼 적지 않습니다**)
- 키 값, 비밀번호, 토큰
